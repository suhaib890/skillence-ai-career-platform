# Deploying Skillence

**Frontend → Netlify** (Next.js) · **Backend → Render** (FastAPI)

The repo is a monorepo:
- `backend/` — FastAPI app (deployed to Render via `render.yaml`)
- `frontend/` — Next.js app (deployed to Netlify via `netlify.toml`)
- `models/` — trained ML artifacts (committed; the predictor needs these for "ensemble" mode)

> **Data note:** the backend uses **ephemeral SQLite** — every deploy and every free-tier
> spin-down resets the database (users, admin, assessments). To persist, add a Render
> PostgreSQL DB and set `DATABASE_URL` (see the commented section in `render.yaml`).

---

## 0. Push the code to GitHub (one time)

git has already been initialized with an initial commit. Create an empty repo on
GitHub (no README), then:

```bash
git remote add origin https://github.com/<you>/skillence.git
git branch -M main
git push -u origin main
```

---

## 1. Backend on Render

For Supabase on Render, set `DATABASE_URL` to the Supabase **Session pooler**
connection string, not the direct `db.<project-ref>.supabase.co:5432` database
host. The direct Supabase host can resolve to IPv6 and fail on Render with
`Network is unreachable`.

Use this shape:

```bash
postgresql+psycopg2://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require
```

1. Render Dashboard → **New → Blueprint** → connect your GitHub repo.
2. Render reads `render.yaml` and proposes the **skillence-api** web service. Apply it.
3. Set these environment variables on the service (Dashboard → Environment):
   - `CORS_ORIGINS` → your Netlify URL (you'll have it after step 2). Temporarily set
     `*` or skip; come back and set it precisely.
   - `ADMIN_EMAIL` → `khanauj60@gmail.com` (or your own)
   - `ADMIN_PASSWORD` → a strong password (overrides the in-repo default)
   - `AUTH_SECRET` → auto-generated by Render (leave it)
   - `LLM_API_KEY` → optional (leave empty for the deterministic engine)
4. Deploy. First build is slow (compiling the ML stack). When live, verify:
   `https://skillence-api.onrender.com/health` → `{"status":"ok",...}`

Copy the service URL (e.g. `https://skillence-api.onrender.com`).

> Free-tier services sleep after ~15 min idle; the first request then takes ~30–50s to wake.

---

## 2. Frontend on Netlify

1. Netlify → **Add new site → Import from Git** → pick the repo.
2. Netlify reads `netlify.toml` (base `frontend`, Next plugin). Leave build settings as detected.
3. **Before the first build**, add an environment variable
   (Site settings → Environment variables):
   - `NEXT_PUBLIC_API_URL` = your Render URL, e.g. `https://skillence-api.onrender.com`
   (This is baked in at build time — changing it later requires a redeploy.)
4. Deploy. Copy the site URL (e.g. `https://skillence.netlify.app`).

### CLI alternative (frontend only, no GitHub needed)
`netlify-cli` is installed. From the repo root:
```bash
netlify login
netlify deploy --build --prod    # set NEXT_PUBLIC_API_URL in the site env first
```

---

## 3. Close the loop (CORS)

Back on Render, set `CORS_ORIGINS` to the exact Netlify URL and redeploy:

```
CORS_ORIGINS=https://skillence.netlify.app
```

(Multiple origins are comma-separated. Include any custom domain too.)

---

## 4. Verify

- Visit the Netlify URL → onboarding/assessment should hit the Render API.
- Admin: go to `/login`, sign in with your `ADMIN_EMAIL` / `ADMIN_PASSWORD` → `/admin`.
- If API calls fail with CORS errors, recheck step 3 (exact scheme + host, no trailing slash).

## Deploy order recap
1. Push to GitHub →
2. Deploy **backend** (get its URL) →
3. Set `NEXT_PUBLIC_API_URL`, deploy **frontend** (get its URL) →
4. Set backend `CORS_ORIGINS` to the frontend URL, redeploy backend.
